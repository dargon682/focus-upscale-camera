# 迭代 v0.8.50：账号权限 · 插件市场 · 语言包 · 行为采集 · 下载增强 · 扩展包

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为全能相机引入可在线部署的后端账号/权限体系、数据式插件市场与语言包、压缩分批行为采集、更稳健的下载引擎，以及扩展包 + beta 计划，版本号升级为 `0.8.50(N)`。

**Architecture:** 纯 Android 客户端 + Cloudflare Workers 无服务器后端。账号/插件市场等**结构化主数据经后端用 GitHub Contents API 写入本仓库 `server-data/` 目录（JSON 为准，满足"保存至 GitHub"）**；会话 token 与临时态存 KV；**高频行为数据存 D1 数据库**（客户端压缩后每隔一段时间批量上传）。插件市场中的插件一律为**数据式资产包**（语言包/滤镜参数/主题配色），由客户端内置解释器执行，**不做任何运行时 DEX 加载**。客户端保持现有"编译期插件 + 控制台日志 + 主题 Token"的既有架构，新增可插拔的插件类型 `LANGUAGE`。

**Tech Stack:** 客户端 Java 17 / CameraX / 原生 View；后端 TypeScript + Cloudflare Workers + KV + D1；数据源 GitHub REST Contents API；认证 JWT（secret 存 Worker secret）。

## 三、共享契约（所有子系统共用，改此文件需同步）

### 3.1 权限分级（权限为标量等级，每用户一个等级）

| level | 名称 | 授权天数 | 能力 |
| --- | --- | --- | --- |
| `none` | 封禁 | — | 登录被拒 / 会话失效，**不可使用本应用** |
| `user` | 默认用户 | 180 | 仅内置插件 + 被管理员批准的插件 |
| `user_pro` | 超级用户 | 360 | 可使用其他开发者上传的插件 |
| `developer` | 开发者 | 10000 | 可上传自定义插件 |
| `admin` | 管理员 | 永久 | 管理面板、改各级权限、改授权期、导出行为、批量分发、插件市场上架审批 |

排序数字（用于比较不可高于当前）：`none=0, user=1, user_pro=2, developer=3, admin=4`。
- `authExpireAt`：epoch 毫秒；`-1` 表示永久（仅 admin）。授权过期 → 按 `none` 处理（不可用，需向管理员续期）。
- 提权一律走"申请 → 管理员审批"；`user_pro→developer→admin` 不可自助越级。

### 3.2 用户对象（`server-data/users/{id}.json`）

```json
{
  "id": "AbCdEf12345GhIjK",
  "username": "zhang_san",
  "email": "zhang@example.com",
  "passwordHash": "$2b$12$...",
  "level": "user",
  "authExpireAt": 1810000000000,
  "status": "active",
  "createdAt": 1800000000000,
  "lastLoginAt": 1801000000000,
  "emailVerified": true,
  "pendingRegistration": false
}
```
- `username` 唯一、不可重复；`id`=15 位随机，字符集 `[A-Za-z0-9]`，唯一，注册时生成。
- 注册需邮箱验证（验证队列存 KV，含 6 位码，10 分钟有效）；管理员**批量分发不需要邮箱**（`emailVerified=false`，账号名由管理员指定，注册态直接可用，首次登录无邮箱、README 或管理员可补绑）。
- 管理员内置账号：`username=admin`，密码 `dargon@zbh`，`level=admin`、`authExpireAt=-1`，创建于后端首次初始化（seed 脚本）。

### 3.3 GitHub 存储布局（本仓库 `server-data/`）

```
server-data/
├── users/
│   ├── index.json                 # [{id, username, level, authExpireAt, status}]
│   └── {id}.json                  # 单个用户完整记录
├── market/
│   └── index.json                 # 全部插件工单（含未审批），见 §3.4
├── behavior/
│   └── day=YYYY-MM-DD/
│       └── {userId}-{seq}.json.gz # D1 导出/聚合后的压缩批次
└── meta.json                      # 后端状态：seed 是否完成、schema 版本
```
- 写入走 `POST /api/github/contents`（Worker 内封装 GitHub Contents API，用 `GH_TOKEN` secret）。
- 并发写入以 `index.json` 的 `{id,updated}` 乐观锁 + base64 `sha`（GitHub `if-match`）处理；失败指数退避重试 3 次。
- 账号为**源真（source of truth）**；KV 仅存会话 token，D1 仅存行为数据。

### 3.4 插件工单/市场条目（`server-data/market/index.json`）

```json
{
  "id": "my-cool-filter",
  "name": "胶片青橙",
  "type": "filter|language|theme",
  "uploader": "dev_wang",
  "allowUser": false,
  "downloadUrl": "https://github.com/dev_org/filter-repo/releases/...",
  "approved": false,
  "sha256": "…",
  "data": { "kind": "preset", "payload": { …类型相关… } }
}
```
- 开发者上传 → `approved=false` 入列；管理员批准 → `approved=true` 才出现在市场。
- **权限可见性**：`user` 仅可见 `approved=true`（且 `allowUser=true` 的）；`user_pro` 可见全部 `approved=true`（含 `allowUser=false` 的）；`developer` 多出"我的上传"管理。
- 应用只下载 `data`（数据式），不下载/执行第三方代码。

### 3.5 数据式插件类型

| type | data.payload | 客户端解释器 |
| --- | --- | --- |
| `language` | `{"strings":{key:value}}` 覆盖 strings.xml 键 | `LanguagePack` 资源层（新增 PluginKind=LANGUAGE） |
| `filter` | `{"preset":{contrast,saturation,brightness,curve:[…]}}` | `FilterPlugin` 新增参数化 preset 应用路径 |
| `theme` | `{"palette":{tokWindowBg:…,tokTextPrimary:…,…}}` | `ThemeManager.overlayTints()` 动态覆盖 token |

### 3.6 版本号方案 `X.Y.Z(N)`

- `X.Y.Z` 为应用主体版本；`N` 为已启用的扩展包数量（数据资产包）。
- 本轮基础版本拟升为 `0.8.50`，显示形如 `0.8.50(0)`、`0.8.50(1)`…
- `version.json` 增加 `baseVersion` 与 `extensions` 字段；`build.gradle.versionName` 仍为 `0.8.50`，`(N)` 由运行时在 About/设置页拼接展示。

### 3.7 行为数据管道

- 客户端在"用户体验增强计划"开启后（默认关闭，需声明书同意）才采样。
- 事件 JSON → 客户端 gzip 压缩 → 攒批（阈值：满 32KB 或距上次上传 ≥ 10 分钟）→ `POST /behavior/ingest`（带 token）。
- 后端解压 → 落 D1（表 `events(id,uid,ts,type,payload)`）→ 管理员导出时按日聚合压缩写入 `server-data/behavior/` 并回传 .json.gz。
